# Decision log

Running log of architecture decisions. Newest last. Format: date — decision — why.

- **2026-10-19 — Project lives at the repository root** (not a `coding-orchestrator/`
  subfolder). The package/CLI is still `coding-orchestrator` / `orchestrator`. Chosen by
  the user.
- **2026-10-19 — Integer IDs + human short IDs** (`T-12`, `R-34`). Simple joins, and
  artifact paths (`runs/<int>`) can't be traversal vectors.
- **2026-10-19 — Alembic owns the schema.** `0001_baseline` was autogenerated from the
  models, then rewritten to plain SQLAlchemy types so it doesn't depend on SQLModel
  internals. A test checks models and migrations for drift.
- **2026-10-19 — Timezone-aware UTC timestamps.** SQLModel ≥ 0.0.48 maps datetimes to
  `UTCDateTime`, which rejects naive datetimes.
- **2026-10-19 — Deterministic Supervisor; the LLM Supervisor only recommends.** Gate
  decisions (verification, review trigger, accept/requeue/block, merge) live in
  `supervisor_service`. LLM supervisor profiles exist for recommendations only, per spec.
- **2026-10-19 — Fail-closed review parsing.** Ambiguous output, or a VERDICT line that
  disagrees with the JSON verdict, becomes CHANGES_REQUESTED. Missing artifacts downgrade
  APPROVED.
- **2026-10-19 — Bounded review loop.** CHANGES_REQUESTED requeues the Worker on the same
  branch, up to `max_review_rounds` (3), then blocks for a human, so automated retries
  can't burn tokens forever.
- **2026-10-19 — Agent/cron tasks skip the Architect** unless they are high-risk, so
  background jobs don't spend Opus tokens.
- **2026-10-19 — Handoff file inside the worktree** at `.orchestrator/handoff.json`, added
  once to the repo's local `info/exclude`. Many harnesses restrict writes to their cwd,
  and the exclude keeps it out of commits.
- **2026-10-19 — Cross-process cancellation via a `CANCEL` marker file** in the run
  directory, polled by the process runner, so `orchestrator task cancel` works even when
  the run lives in the server process.
- **2026-10-19 — WebSocket tails artifact files** instead of an in-memory bus only, so runs
  started from the CLI stream to the GUI too.
- **2026-10-19 — Recovery commits never stage sensitive files** (`.env`, keys,
  credentials); those stay untracked.
- **2026-10-19 — Anthropic: no `temperature`, use `effort`.** The installed SDK (1.x) no
  longer accepts sampling params, and Claude Opus/Sonnet 5.5 reject them. Refusal fallback
  is on by default with `fallbacks="default"`.
- **2026-10-19 — Qwen provider defaults to the Token Plan endpoint**, by the user's choice,
  despite Alibaba's terms restricting Token Plan to interactive tool use. The warning is
  documented in README, providers.md, `.env.example`, and the provider row's notes.
- **2026-10-19 — Primary supervisor = `qwen3.8-max`, Sonnet alternate**, by the user's
  choice (lower cost).
- **2026-10-19 — Worker profiles on Token Plan IDs**: `qwen3.8-flash`,
  `deepseek-v4.1-flash`, `glm-5.3`, all listed by Model Studio. DeepSeek's own API uses
  `deepseek-flash`.
- **2026-10-19 — Adapter defaults:** Qwen Code binary corrected to `qwen -p`, and OpenCode
  to `opencode run "<msg>"` (the spec's `--prompt-file` flag doesn't exist there). DeepSeek
  Harness and ZCode keep the spec's placeholders, explicitly marked unverified.
- **2026-10-19 — Tailwind v4 with `tailwind.config.js` via `@config`** to keep the spec's
  file layout while using the current major version. Frontend: React 19, Vite 8,
  TypeScript 7.
- **2026-10-19 — APScheduler 3.x** (stable line; 4.x isn't stable). Cron is evaluated in UTC.
- **2026-10-19 — Fallback UI is a single static HTML file** with no build step and no
  dependencies, served when `web/dist` is missing.
- **2026-10-19 — Architect runs through `claude -p` on the user's Claude Pro subscription**
  (new `claude_cli` provider kind, profile `architect-claude-cli`, preferred over
  `architect-opus`). Basis: Anthropic's Help Center allows `claude -p` on subscription
  limits, and its legal page reserves OAuth for native Anthropic apps. So the orchestrator
  launches only the unmodified binary, never handles the token, and never forwards
  `ANTHROPIC_API_KEY`. All tools are disabled (`--tools ""`, MCP denied) to enforce the
  Architect's no-execution rule, and calls are serialised. No schema change was needed
  (`providers.kind` is a free string).
- **2026-10-19 — Claude Code Worker adapter no longer forwards `ANTHROPIC_API_KEY`**, for
  the same reason (subscription auth, no silent API billing).
- **2026-10-19 — Qwen default stays on the Token Plan** (user's decision, reconfirmed after
  learning that the interactive-only rule covers every model on the plan, DeepSeek/GLM
  included, and also covers Qwen Cloud's Token Plan).
- **2026-10-19 — RESOLVED: Token Plan usage by the harness is permitted** (Alibaba Cloud
  International Support, written reply). Tasks triggered manually, each running
  `qwen -p` (or calling the standard API), are "fully permitted". Conditions: no
  high-frequency automated scripts, no account sharing, no training of third-party models,
  use the plan's own key and base URL, and keep the key out of public repos. DeepSeek and
  GLM models on the Personal Edition are included. Model Studio judges request patterns at
  the API level, not by client tool. **Decision: keep the current path** (Token Plan
  default, headless harness runs). The Token Plan guard and Interactive Worker mode are
  **parked**. Revisit them if usage becomes high-frequency or scheduled, or if the
  published terms change.
- **2026-10-26 — Harness routing by worker model, ordered by token efficiency.** The
  first-request overhead of 10 harnesses was measured against a local mock API
  (`scripts/harness-bench`). It ranges from ~0.7k (Aider) to ~13k + a ~6k side call
  (stock Qwen Code). Published per-task totals differ about 7× (DeepSeek Harness vs
  Claude Code/OpenCode on DeepSeek V4). Defaults: `deepseek*` → DeepSeek Harness, `qwen*`
  and `glm*` → Pi, then Qwen Code (Qwen) and OpenCode. The routes are overridable with
  the new `harness_routing` setting, a key in the existing settings table, so there is no
  schema/API change. Existing harness tags and explicit assignment still take precedence.
- **2026-10-26 — Per-run harness token usage in `runs.usage`** (existing column), parsed
  from each harness's JSON output (Pi, dsh, Qwen Code, OpenCode, Claude Code) or Aider's
  `Tokens:` lines. Routing switches to the lowest weighted tokens per accepted task once
  at least two candidates each have ≥ 3 accepted tasks on the model. There's no
  automatic exploration. Parsers live in `adapters/common.py`, outside the frozen
  adapter interface. Adapters only override `run`/`parse_result`.
- **2026-10-26 — Adapter fixes from real CLI runs:**
  - **DeepSeek Harness:** the real headless form is `dsh --profile headless --json -`
    (the spec's `run --cwd --prompt-file` didn't exist). It is routed to any
    OpenAI-compatible endpoint (Token Plan by default) via a per-run `DSH_HOME` patch.
  - **Qwen Code:** `--approval-mode auto-edit` hid the shell tool in `-p` mode, so
    `--allowed-tools run_shell_command` is added (shell is auto-approved inside the
    isolated worktree). Managed auto-memory is off (it cost a ~6k-token extra call per
    run), and `skill`/`notebook_edit` are excluded.
  - **Pi:** new adapter.
  - **Upgrade path:** unedited rows holding a previous default template are upgraded at
    seed time; edited rows are left alone.
- **2026-10-26 — Explicit cache markers only inside harness agent loops.** Pi/dsh send
  `cache_control` (system, last tool, newest message) for `qwen3.8-max`/`qwen3.8-flash`.
  Those are the explicit-cache models on Qwen Cloud: 10% hit vs 20% implicit, 125% write,
  5-minute TTL. DeepSeek/GLM are implicit-only, so they get no markers. The
  orchestrator's own single provider calls stay on the implicit cache, because they
  rarely recur within 5 minutes.
- **2026-10-26 — Redaction no longer hides token counts.** Keys ending in `tokens` with
  an all-digit value (`"inputTokens": 400`, `max_tokens=16000`) are usage numbers, not
  secrets. Singular `token` keys are still redacted.
- **2026-10-26 — Saved agents and agent schedules (revision `0002_agents`).** These are
  additive contract changes: a new `agents` table, nullable soft-reference
  `tasks.agent_id` and `schedules.agent_id` (no FK, so deleting an agent keeps its
  tasks), and new `/api/agents` routes plus `DELETE /api/schedules/{id}`. Existing
  request and response shapes only gain optional fields. An agent run is an ordinary task
  with an assigned profile and harness. With a project it is `coding` and fully gated;
  without one it is `agent` (direct API). Schedules on Token Plan models that fire more
  than once a day get a warning, not a block. See `agents.md`.
- **2026-10-26 — GUI design: Qwen Cloud-style light and dark themes.** The tokens come
  from qwencloud.com: Inter / Roboto Mono, ink `#0B0C0F`, page `#F9FAFD`, panels
  `#F2F4F8`, borders `#E6E9EF`, violet accent `#653AFF` on `#F1EDFF`, the
  violet→pink→orange heading gradient, 18px cards and pill buttons. The dark theme uses
  the same shapes with a matching dark palette. Fonts ship with the build (`@fontsource`),
  so there are still no external requests. The theme is a per-browser preference (default
  System), applied before first paint. This replaces the spec's "dark by default"; the
  server `theme` setting is kept for API compatibility. No Qwen logos or brand marks are
  used.
